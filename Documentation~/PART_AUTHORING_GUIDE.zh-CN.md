# Avatar Part Assembler 部件制作指南

这份指南面向要发布可被其他 Avatar 使用的部件作者。它描述的是当前 `0.4.0` 版本的实际工作流：
部件在制作阶段依赖一个参考 Avatar，发布时交付一个 Profile 和一个可移植的部件预制体，使用者只需要把预制体
放到自己的 Avatar 下。

如果只想安装别人制作好的部件，请先阅读仓库根目录的 [`README.md`](../README.md)。如果需要了解装配器内部的
事务、预览和 NDMF pass，再阅读 [`OVERVIEW.md`](OVERVIEW.md)。

## 1. 先理解 APA 会做什么

一个部件 Profile 描述“部件如何替换一个目标渲染器”：

1. 找到 Avatar 中的目标 `SkinnedMeshRenderer`。
2. 从目标网格中移除 Profile 声明的三角形集合。
3. 读取部件网格的顶点、三角形、蒙皮、形态键、UV、材质和骨骼。
4. 按 Profile 中保存的一对一接缝配对，把部件接缝顶点焊接到目标顶点；UV 语义不一致时保留分裂顶点。
5. 生成新的目标网格和最终骨骼表。
6. 将部件渲染器上的动画路径重定向到生成后的目标渲染器，并在源对象确实为空时删除源对象。

预览、Play Mode/Gesture Manager 和最终上传构建都走同一个 NDMF 装配入口。制作窗口中的“验证”和“试运行装配”
不创建最终网格，但会尽可能提前执行同一套规则。

## 2. 资产清单：哪些需要创作、哪些需要发布

### 2.1 制作阶段必须准备

| 资产 | 用途 | 是否随部件发布 |
| --- | --- | --- |
| 参考 Avatar 场景或测试场景 | 提供目标渲染器、目标骨架和目标网格 | 否。它是作者的制作参考 |
| 部件模型源文件（FBX、Blend 等） | 生成部件网格、骨骼和形态键 | 通常不直接发布，可按项目许可选择 |
| 部件网格资产 | `Renderer` 使用的实际 Mesh | 是，通常嵌在预制体或模型资产中 |
| 部件骨架与蒙皮 | 让部件随 Avatar 骨骼变形 | 是，作为部件预制体内部层级 |
| 部件材质与贴图 | 渲染部件子网格 | 是，必须是项目资产 |
| 接缝顶点色 | 标记部件侧允许参与配对的顶点 | 是，必须保留在导入后的 `Mesh.colors32` 中 |
| 黑白移除遮罩纹理 | 生成目标网格的待移除三角形集合 | 否。Profile 只保存生成后的三角形地址 |
| 动画片段、控制器、Merge Animator | 可选，用于部件形态键或部件属性动画 | 需要动画功能时随预制体发布 |

### 2.2 APA 会生成的发布资产

建议为每个部件建立独立目录，例如：

```text
Assets/MyPart/
├─ Meshes/MyPart.fbx
├─ Materials/MyPart.mat
├─ Textures/MyPart_BaseColor.png
├─ Profiles/MyPart.asset
├─ Prefabs/MyPart.prefab
├─ Animations/          （可选）
└─ Documentation/       （可选，作者自己的安装说明）
```

最终至少应交付：

- `MyPart.asset`：由窗口的 **Save Profile Asset** 生成的 `ApaPartProfile`。
- `MyPart.prefab`：由 **Create Part Prefab** 生成，根节点带 `AvatarPartInstaller`。
- Profile 中引用到的部件网格、材质、贴图和动画资产。

不要把参考 Avatar、参考场景中的目标身体网格、场景材质或临时对象一起打包进部件预制体。

### 2.3 受保护网格模式：额外的发布资产与分发规则

在 Output 区块打开 **Protect the part mesh** 后，**Create Part Prefab** 会用另一种方式发布同一个部件：

| 资产 | 内容 | 是否随部件发布 |
| --- | --- | --- |
| `Prefabs/MyPart.prefab` | 根节点带 `AvatarPartInstaller`；安装器引用受保护资产，部件渲染器保存为**没有网格** | 是 |
| `Prefabs/MyPart_ProtectedMesh.asset` | `ApaProtectedMeshAsset`：版本化的二进制载荷（盐、IV、密文、HMAC），不含任何 Unity 网格引用 | 是，必须与预制体一起交付 |
| 源网格 / FBX | 载荷的来源 | 否。受保护模式的意义就是不再分发它 |

分发规则：

- 预制体与 `_ProtectedMesh.asset` 是一个整体。只交付预制体时，使用者会得到 `APA053 PROTECTED_MESH_INVALID`
  的阻断诊断（`reason=protected-mesh-missing`），而不是一个可以凑合用的空网格部件。
- 受保护资产是工程内的普通资产，会保留自己的 GUID。替换载荷时 GUID 不变，已经引用它的预制体继续可用。
- 载荷的指纹不会自动刷新。源网格改变后必须重新创建受保护预制体；否则构建会以指纹不匹配阻断。
- 载荷使用包内派生的密钥。这保护的是**分发格式**并能检测篡改，**不是不可提取的 DRM**：构建在编辑器内运行，
  有能力的接收者可以观察内存中的解密结果。
- 受保护模式只覆盖部件渲染器的网格数据。材质、贴图、骨骼、动画和 Profile 仍然是普通资产引用，必须照常交付。
- 如果部件根下还有别的组件引用同一个源网格或它的模型文件（例如 `MeshCollider`、第二个渲染器），创建会以
  `APA054 PROTECTED_MESH_SOURCE_LEAK` 拒绝并回滚，不会发布一个仍然依赖源网格的预制体。

创建时的行为（**Create Part Prefab**、覆盖已有预制体、以及把预制体实例转成独立预制体三种路径都一样）：

1. 先在内存中把部件网格读取为快照并加密成载荷；这一步失败时工程仍未被改动。
2. 保存预制体、清除部件渲染器的网格引用、把受保护资产写到 `<预制体名>_ProtectedMesh.asset`。
3. 复查写出的预制体：安装器必须真的引用载荷、部件渲染器必须真的没有网格、并且预制体的依赖里不能再出现源网格或
   它的模型文件。任何一条不成立就回滚预制体与载荷，并给出精确诊断。

预览与构建的行为：

- 预览、Play Mode 和最终上传都会在内存中解密同一份载荷，并装配出与未受保护时相同的几何体；解密结果不会写回工程、
  也不会写进场景或预制体。
- 载荷按内容身份缓存，重复的 Scene View 重绘不会反复解密；未受保护的部件完全不会进入编解码器。
- 作者窗口的接缝候选、合并检查、UV/材质推断等叠加层会读取内存中重建的几何体，关闭窗口或切换选择时会释放它。

## 3. 创作者的强制约束

下面的约束是 APA 的数据契约。违反后，验证或构建会阻断；不要通过提高容差、清除错误或手工改 Profile
来绕过它。

### 3.1 层级与渲染器

- 目标对象必须是 `SkinnedMeshRenderer`，并且位于你选择的 Avatar 根对象下。
- 部件根对象必须包含你在窗口中选择的部件渲染器；部件渲染器必须位于部件根对象下。
- 目标 Avatar 根和部件根都必须在制作场景中明确选择。不要让 Profile 依赖“当前选中对象”或某个偶然的父节点名称。
- 目标身体引用只用于制作期捕获路径和签名。发布的部件预制体不应保存参考场景的目标渲染器引用；目标会在使用者的
  Avatar 层级中按 Profile 记录的路径和签名解析。

### 3.2 稳定部件 ID

- 使用窗口的 **Assign** 为部件生成稳定 ID，并把它当作发布后的永久身份。
- ID 不应由显示名称、父对象名称、文件名或安装位置推导；重命名部件或移动预制体不能改变 ID。
- 同一个 Avatar 上安装的多个部件不能使用相同 ID。改做一个有实质不同的部件时，创建新的 ID，而不是复用旧 Profile。

### 3.3 网格导入与静置姿势

- 目标网格和部件网格在制作和验证时都必须可读（Unity Mesh Import Settings 中启用 **Read/Write**）。
- 导入后检查顶点数量、子网格、UV、顶点色、骨骼和形态键没有被导入器丢弃或重排。
- 部件必须在与目标 Avatar 相同的静置/绑定姿势下建模。接缝生成使用世界空间位置，而不是只看局部坐标。
- 目标和部件的 Transform、父级缩放和旋转必须是你希望发布的绑定状态；不要用大容差掩盖未应用的建模变换。
- 顶点、UV、法线、切线、形态键增量和骨骼权重不能包含 NaN 或 Infinity。

### 3.4 接缝顶点色：只标记部件侧

APA 当前不从非骨骼顶点组读取接缝候选，而是读取部件网格的 `Mesh.colors32`：

- 在建模软件中给“允许被合并到身体”的部件顶点写入同一个顶点色。
- 在 Part Authoring 窗口的 **Candidate Color Code** 中填写相同的色号。默认值是 `#000000`。
- 比较是 `Color32` 四通道精确相等，包含 alpha；没有颜色容差。`#00FF00` 和 `#00FE00` 不是同一个颜色。
- 必须确保导出器和 Unity 导入设置保留顶点色，且颜色数量与顶点数量一致。
- 没有候选颜色、顶点色数量不匹配或一个顶点都没有命中时，APA 会阻断；不会退回“把所有部件顶点都当候选”。
- 目标身体不需要顶点色。目标侧的候选集合是目标网格顶点，最终通过世界空间位置匹配。

候选顶点色只控制“部件哪些顶点可以参与接缝”。它不会自动移除目标三角形，也不会替代接缝生成步骤。

### 3.5 骨架与权重

- 目标骨架和部件骨架必须在窗口中分别选择。两者应处于相互对应的骨骼层级；**Suggest Armatures** 只是建议，作者必须复核。
- 骨骼身份是“相对于各自所选骨架的路径”。相对路径相同就表示同一关节；目标身体的骨骼是最终权威，部件权重会重定向到它。
- 所有有效权重都必须指向部件骨架内的真实骨骼。清理导出文件中没有实际影响顶点的孤立权重组、丢失骨骼和无效索引。
- 每个顶点必须有一条有效权重记录；有效权重和必须大于 `1e-5`。权重不能为负数，也不能包含 NaN/Infinity。
- **接缝顶点不得带有 Avatar 没有的有效骨骼权重。** 接缝处如果由部件独有骨骼影响，焊接后目标身体无法提供相同的骨骼变换，动画时会出现裂缝或错位。
- 不要在部件中复制一套路径相同但 Transform 不对应的身体骨骼。若相对路径相同，目标骨骼会被采用；若身体出现重复路径，构建会阻断。
- 目标骨架中未被身体顶点实际使用的骨骼仍可能作为“声明的身体身份”拥有权威；不要用部件骨骼去抢占同一路径。

### 3.6 形态键

- 同名形态键会合并成一个最终形态键；两侧必须有相同的帧数量和完全相同的帧权重。
- 同名形态键在焊接接缝处的位移、法线和切线增量必须一致，否则无法安全合并。
- 部件独有形态键可以保留，但焊接接缝顶点的所有增量必须为零。否则该形态键会移动一个最终属于身体的顶点，构建会阻断。
- 只有在确认独有形态键的接缝增量为零时，才勾选 **Allow Part-Only Blend Shapes**；这个开关不能放宽同名形态键的严格检查。
- 在导出前检查形态键名称没有重复、空名称或多余空格，并确认形态键数量和帧权重没有被导入器改变。

### 3.7 UV 与材质语义

- UV 使用“语义名称 → 源 UV 通道”映射，而不是把 Unity 通道编号当成跨部件身份。语义名会去除首尾空格，并按大小写敏感方式比较；不要为同一语义填写两行。
- 使用 **Infer From Part Mesh** 后逐行复核，尤其是 UV0/UV1 等通道是否真的对应你希望保留的语义。
- 同一语义在接缝两侧的 UV 值不一致时，APA 会保留部件侧分裂顶点（诊断 `APA045`），以避免静默丢失 UV。需要真正焊接的通道必须相同。
- 材质语义使用“语义名称 → 部件子网格 → Material 资产 → 策略”。材质文件名不是语义名。
- Material 必须是项目资产，不能引用只存在于制作场景的材质。根据目标 Avatar 的材质布局选择 `Auto`、`Use Target`、`Keep Part` 或 `Force New`。
- 配置文件里的 Material 是**创作默认值**：构建与预览实际采用部件渲染器该槽位当前的 `sharedMaterials[子网格]`，只有渲染器该槽位不存在或没有材质时才回退到配置文件中的资产。因此安装者在渲染器（或预制件实例）上替换材质会直接成为构建使用的材质，而且不会被写回配置文件。
- 每一个部件子网格都应有明确材质语义；不要留下“没有最终材质槽位”的子网格。

## 4. 从建模文件到可发布部件

### 步骤 0：建立参考场景

1. 复制一份只用于制作的 Avatar 场景，保存原始工程资产的备份。
2. 将待替换的目标身体渲染器和部件放入同一静置姿势。
3. 不要在参考场景里应用破坏性替换；APA 读取快照，最终修改只发生在预览/构建临时对象。
4. 确定部件的替换范围、目标渲染器、接缝环和需要保留的 Avatar 骨骼。

### 步骤 1：准备部件模型

1. 在 DCC 中完成几何、法线、切线、UV、材质、骨架和形态键。
2. 将 Transform、单位和静置姿势固定为发布时的状态。
3. 为部件接缝环写入候选顶点色，并确认颜色覆盖的是顶点而不是只覆盖面材质。
4. 清理接缝上的部件专属骨骼权重，清理孤立骨骼和零和权重。
5. 导出并在 Unity 中重新检查网格属性；不要只在 DCC 视口中确认。

### 步骤 2：设置 Unity 导入

1. 选中部件模型资产，启用 **Read/Write**，确认 Mesh、顶点色、UV、骨骼和形态键都存在。
2. 检查 Mesh 的顶点数、子网格数、骨骼列表和形态键列表。
3. 将材质和贴图转换为项目资产，不要保留仅属于 FBX 内嵌场景的临时引用。
4. 如果使用动画，确认动画片段和控制器也是项目资产，并且 Merge Animator 使用部件预制体内的相对路径。

### 步骤 3：打开部件编辑器并建立选择

1. 打开 `Tools > Avatar Part Assembler > Part Authoring`（中文界面为“工具 > 部件装配器 > 部件编辑”）。
2. 在最上方先加载已有 Profile；加载新 Profile 时确认窗口中的骨架引用来自当前 Profile，而不是上一次编辑的部件。
3. 填写或确认：Avatar Root、Target Renderer、Part Root、Part Renderer、Target Armature、Part Armature 和 Output Folder。
4. 目标渲染器必须是身体 `SkinnedMeshRenderer`；部件渲染器应来自部件根对象内的实际网格。
5. 使用 **Suggest Armatures** 只能作为起点。检查两个对象的层级，确保选的是对应骨骼根，而不是某个偶然的子骨骼。
6. 在 Part Identity 中分配稳定部件 ID。ID 一旦发布，除非创建全新部件，否则不要修改。

### 步骤 4：捕获目标和部件兼容性

1. 对目标身体执行 **Capture Signature**，或让 Validate/Dry-Run/Save Profile/创建预制体的首次使用流程自动捕获。
2. 签名包含目标网格拓扑、顶点数、子网格索引、形态键、骨骼路径以及内容指纹；它用于发现重新导入或换网格。
3. 如果看到 `APA047` 或 `APA048`，先确认当前网格是否确实是有意修改的。如果是有意修改，重新检查所有属性后再重新捕获；不要只为消除红色提示而盲目重录。
4. 签名一旦捕获，不会因为普通验证自动覆盖。制作过程中替换目标网格后，必须把它当作一次新的 Profile 兼容性确认。

### 步骤 5：用黑白遮罩制作移除区域

APA 当前只通过纹理遮罩生成移除区域；场景拾取、数字地址输入和子网格整批删除不再是作者工作流。

1. 制作一张对应目标网格 UV 的黑白 `Texture2D`。默认白色代表选中、黑色代表保留；启用 **Invert** 可反转。
2. 选择正确的目标 UV 通道。遮罩按目标网格 UV 读取，与部件 UV 无关。
3. 默认阈值为 `0.5`。每个三角形使用 7 个样本：三个顶点、三条边中点和重心；至少 4 个样本达到阈值才选中。
4. 亮度使用 RGB 计算，alpha 被忽略。边界要留出明确的黑白差，不要依赖恰好落在阈值上的灰色。
5. 选择 Apply Mode：Replace 重建集合，Add To Selection 叠加区域，Subtract From Selection 从已有集合扣除。
6. 点击 **Apply Mask**，在 Removal Region 中检查三角形数量和折叠的地址审阅列表。
7. 遮罩纹理只是编辑输入，不会被写进 Profile；如果以后需要重新生成区域，请保留源遮罩和对应的 UV 说明。
8. 打开顶部工具栏的 **Removal Overlay** 只能查看红色区域，不能通过场景点击编辑集合。

### 步骤 6：设置接缝候选并生成显式配对

1. 在 Seam 区域填写候选颜色代码，例如 `#000000` 或 `#RRGGBBAA`。
2. 打开顶部工具栏的 **Candidate Overlay**，确认绿色点只覆盖部件接缝环，不要覆盖会被保留为独立几何的内部顶点。
3. 设置世界单位容差。默认 `1e-4`；允许范围为 `1e-7` 至 `1e-3`。先修正模型对齐，再考虑在范围内调整容差。
4. 点击 **Generate From World Positions**。这一步会读取部件颜色候选与目标空间候选，建立一对一配对并写入当前草稿。
5. 检查 Target seam candidates、Part seam candidates 和 Pairs 数量。两侧数量必须相等，目标顶点不能被多个部件顶点重复占用。
6. 打开 **Merge Check Overlay**：绿色表示在当前候选颜色和容差下会配对，红色表示部件候选没有找到对应目标顶点。该模式只读，不会修改 Profile。
7. 修复所有红点、错误位置和异常数量后，再重新生成一次。不要手工编辑 Profile 中的索引来“凑数量”。
8. 点击 **Clear** 只有在确认该部件不声明接缝时才使用；替换身体区域的部件通常需要一组有效接缝。

### 步骤 7：设置 UV 语义和材质语义

1. 在 UV Semantics 中点击 **Infer From Part Mesh**，逐行确认语义名称和源通道；需要时添加、移动或删除行。
2. 在 Material Semantics 中点击 **Infer From Materials**，确认每个部件子网格、Material 资产、语义名和策略。
3. 对目标和部件实际共享的 UV/材质语义保持稳定命名；不要把一个材质的显示名称当作跨部件协议。
4. 处理窗口显示的 `APA045`、`APA050`、`APA009` 或 `APA038` 后再继续。语义声明缺少实际通道或子网格时，保存不会可靠。

### 步骤 8：确认骨骼和形态键策略

1. 确认两个 Armature 选择仍然存在，并检查窗口显示的相对路径。
2. 保持 **Merge Armature** 开启，除非你明确知道部件不需要骨骼合并。APA 会在构建时生成临时 Modular Avatar Merge Armature，使用已选择的两套骨架，不使用旧的名称前缀/后缀推断。
3. 只在接缝约束已经满足时启用 **Allow Part-Only Blend Shapes**。
4. 检查同名形态键的帧数量、帧权重和接缝增量。若部件只提供局部表情，优先把接缝区域的增量清零，而不是关闭验证。

### 步骤 9：验证、试运行并保存 Profile

1. 点击 **Validate**，先处理 Error，再处理 Warning。重点检查目标指纹、骨架、接缝、权重、UV、材质和形态键。
2. 点击 **Dry-Run Assembly**。它会给出预计输出顶点、三角形、子网格、UV 通道和移除三角形数量，但不会创建网格。
3. 确认预览中的红色移除区域、候选点、接缝点和目标形态键位置都符合预期。
4. 在 Output 中确认 Profile 路径以 `.asset` 结尾、Prefab 路径以 `.prefab` 结尾，并且路径属于项目 `Assets/`。
5. 点击 **Save Profile Asset**。当前新建 Profile 使用 Schema 5；已有 Profile 被覆盖前需要明确确认，保存动作会再次验证和试运行。

### 步骤 10：生成独立部件预制体

1. 点击 **Create Part Prefab**，从当前部件根对象生成预制体并配置 `AvatarPartInstaller`。
2. 如果场景中的部件根来自另一个预制体实例，APA 会复制并解包一个临时副本，生成**原始普通预制体**，不是 Prefab Variant；原场景实例不会被解包或修改。
3. 生成器会检查所有序列化引用。引用制作场景对象、未保存的材质/Profile 或不可证明可移植的引用都会阻断写入。
4. 发布前打开生成的预制体，确认根节点有 `AvatarPartInstaller`、Profile 指向项目资产、Part Root 指向预制体内部对象，且 Target Renderer 不指向参考场景的身体对象。
5. 如果只修改了 Profile 而不想重建几何，使用 **Update Installer On Prefab** 更新已有预制体的安装器字段。
6. 需要保护网格时，先打开 **Protect the part mesh**（见 [2.3](#23-受保护网格模式额外的发布资产与分发规则)），再点击
   **Create Part Prefab**。窗口会显示将要写入的受保护资产路径；如果该路径已存在受保护资产，替换前会再次确认。
7. 受保护预制体生成后，确认：预制体旁的 `_ProtectedMesh.asset` 存在、安装器的 Protected Mesh 指向它、部件渲染器
   的 Mesh 字段为空，并且 **Update Installer On Prefab** 不会改动这两者。

## 5. 动画与形态键部件

如果部件使用 Modular Avatar Merge Animator：

1. 将 `ModularAvatarMergeAnimator` 和其控制器放在部件预制体中，通常使用部件根的 Relative path 模式。
2. 动画曲线应记录部件渲染器的形态键或属性路径，不要预先把曲线改成某个使用者 Avatar 的目标路径。
3. 该部件的目标渲染器会在构建时被 APA 消费，APA 会把 NDMF 已记录的源对象路径映射到最终目标渲染器。
4. 只有成功装配的源渲染器才会重定向；构建失败时不会修改动画路径，也不会清理源对象。
5. 构建成功后，原渲染器组件会被消费；如果源对象只剩 Transform，APA 会清理空对象。仍带子对象、约束、PhysBone 或作者组件的对象会被保留。
6. 在 Play Mode 和 Gesture Manager 中分别检查：动画是否驱动最终目标网格的形态键、部件骨骼是否跟随、源对象是否没有残留空节点。

## 6. 发布前验收清单

### Profile 与预制体

- [ ] Profile 是项目中的 `ApaPartProfile` 资产，Schema 为当前版本支持的版本。
- [ ] 稳定部件 ID 已分配且未与其他部件重复。
- [ ] 目标签名和部件网格指纹已捕获，且是在最终导入设置下捕获的。
- [ ] 目标/部件骨架路径已保存，重新打开窗口后仍能恢复。
- [ ] 预制体是普通预制体，不是意外生成的 Variant。
- [ ] 预制体没有指向参考场景的引用。

### 网格与接缝

- [ ] 目标和部件网格均可读，顶点色、UV、骨骼和形态键都保留。
- [ ] 部件候选顶点使用选定的精确 `Color32`，目标网格不依赖顶点色。
- [ ] 接缝通过世界位置生成并保存为显式一对一配对。
- [ ] Merge Check 中所有应合并点为绿色，没有意外红点。
- [ ] 接缝顶点没有部件专属骨骼有效权重。
- [ ] UV 语义差异是有意的；所有 `APA045` 信息都已理解。

### 形态键、动画与运行

- [ ] 同名形态键的帧数量和帧权重一致。
- [ ] 部件独有形态键在焊接接缝上的所有增量为零。
- [ ] Merge Animator 使用部件内部相对路径，Play Mode 中能驱动最终网格。
- [ ] NDMF 预览与 Play Mode 结果都正确。
- [ ] 删除部件预制体后，原 Avatar 不发生永久变化。
- [ ] 最后一次 Validate、Dry-Run 和实际 Build 都没有未处理的 Error。

### 受保护网格模式（使用该模式时）

- [ ] 预制体旁的 `_ProtectedMesh.asset` 与预制体一起放在交付目录中。
- [ ] 预制体的安装器引用该受保护资产，部件渲染器的 Mesh 字段为空。
- [ ] 预制体的依赖列表里不再出现源网格或其模型文件（在 Project 窗口选中预制体，查看 Inspector 的依赖）。
- [ ] 交付包中不包含源 FBX/网格资产（除非你的许可明确允许）。
- [ ] 在 NDMF 预览中确认受保护部件正常显示，并且材质替换、材质资产修改都会立刻反映。
- [ ] 源网格发生变化后，已经重新创建受保护预制体与载荷。
- [ ] 交付说明中写清“这是分发格式保护，不是 DRM”。

## 7. 常见诊断的处理方向

| 诊断 | 常见原因 | 优先处理 |
| --- | --- | --- |
| `APA001/APA002/APA003` | 接缝数量、空间位置或一对一关系不成立 | 修正静置姿势、候选颜色和容差，重新生成接缝 |
| `APA012` | 目标身体与 Profile 的拓扑或属性签名不同 | 确认是否重新导入/换网格；必要时重新捕获并重新检查全部数据 |
| `APA024` | Profile 签名不完整 | 在最终网格上重新 Capture Signature |
| `APA042` | Profile 仍是旧的无序接缝集合 | 在窗口中按世界坐标重新生成显式配对 |
| `APA043/APA044` | 骨架缺失、超出根对象或加权骨骼不在选定骨架 | 重新选择对应骨架并修复权重层级 |
| `APA045` | 同名 UV 语义在接缝两侧不同 | 如果需要真焊接，统一 UV；否则确认分裂顶点是有意的 |
| `APA047/APA048` | Profile 缺少或不再匹配目标网格指纹 | 检查导入设置和源网格后重新捕获 |
| `APA049` | 接缝顶点引用了目标不存在的有效骨骼 | 清除接缝上的部件专属权重 |
| `APA050` | Profile 声明的 UV 通道不存在 | 修正语义行或补齐网格 UV |
| `APA052` | 候选颜色代码或部件顶点色不可用 | 使用有效 `#RRGGBB/#RRGGBBAA` 并重新导入保留顶点色的网格 |
| `APA053` | 受保护载荷缺失、被篡改、被截断、属于别的部件，或版本不受支持 | 查看 `reason=`：把 `_ProtectedMesh.asset` 与预制体一起交付，或重新创建受保护预制体 |
| `APA054` | 受保护预制体仍然依赖源网格或其模型文件 | 移除其它组件对源网格的引用（例如 `MeshCollider`、第二个渲染器）后重新创建 |
| `APA006` + `reason=missing-part-mesh` | 普通部件渲染器没有网格，且安装器没有可解码的受保护载荷 | 指定源网格，或改用受保护网格模式重新创建预制体 |

## 8. 给使用者的交付说明模板

发布部件时，建议至少附带以下信息：

```text
部件名称：
部件 ID：
适用目标渲染器/Avatar：
需要替换的身体区域：
需要的 APA 版本：0.4.0 或更高的兼容版本
是否包含动画：是 / 否
是否包含独有形态键：是 / 否
安装方式：将 <PartName>.prefab 拖到 Avatar 根对象下
卸载方式：删除该预制体
已验证：NDMF 预览 / Play Mode / Gesture Manager / 上传构建
已知限制：
```

部件作者应同时发布 Profile 与预制体，不要要求使用者手工填写接缝索引、手工绑定目标渲染器或在目标 Avatar
上安装一套额外的合并脚本。
